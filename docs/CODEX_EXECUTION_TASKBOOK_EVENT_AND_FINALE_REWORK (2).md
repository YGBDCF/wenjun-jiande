# 4. 统一内容规格

以下规格适用于全部83个普通事件。

## 4.1 开场正文字数

每个普通事件开场正文：

- **最低：100个汉字**
- **建议：110—160个汉字**
- **上限：200个汉字**

不计标题、按钮、数值和结果反馈。

正文必须包含：

- 时间或光线；
- 地点；
- 至少一个人物动作；
- 至少一个具体物件；
- 当前矛盾；
- 当前天气或环境影响。

## 4.2 选项数量

每个事件：

- 至少3个选项；
- 原有事件若已有4个固定选项，必须保留4个；
- 不得减少；
- 83个事件至少应有249个独立分支。

## 4.3 按钮文字

每个按钮：

- 建议8—22个汉字；
- 必须是一个明确动作；
- 不得只写属性倾向。

禁用按钮：

```text
动手解决
核对记录
先照料人
认真处理
认真完成
帮忙
继续观察
暂时离开
请求帮助
做正确的事
选择学习
选择道德
选择实务
```

同一按钮文本全局不得重复，确有必要时最多出现2次。

## 4.4 每个选项的结果反馈

每个结果反馈：

- 最低50个汉字；
- 建议60—120个汉字；
- 上限160个汉字。

必须包含：

1. 玩家执行的具体动作；
2. NPC或环境的即时反应；
3. 当前问题的收束；
4. 后续影响的自然提示。

## 4.5 每个选项的数值结果

每个选项至少有一种非零变化，并至少有一种后续影响。

允许的影响：

- 玩家属性；
- 健康、体力；
- 人物关系；
- 校园秩序；
- 公共资源；
- 地点状态；
- 周考准备度；
- 报纸可信度；
- 社团进度；
- 事件权重；
- 后续旗标。

普通事件的核心属性变化建议：

```text
-2 至 +4
```

关键事件：

```text
-4 至 +6
```

不得出现普通事件一次增加10点核心属性。

## 4.6 选择必须有代价

每个事件至少一个选项存在明确代价，例如：

- 消耗体力；
- 延误进度；
- 消耗资源；
- 错过另一项机会；
- 某人物轻微失望；
- 次日产生续接任务。

不得设计三个选项都只增加不同属性且没有代价。

# 12. T05：选择后的四层反馈系统

## 目标

每次玩家选择后都能看见具体后果。

## 固定展示顺序

```text
结果剧情
→ NPC/环境反馈
→ 数值变化
→ 后续影响
→ 进入下一个时段
```

## UI时长

- 结果剧情必须由玩家点击继续；
- 数值变化显示不少于1.2秒，或由玩家点击关闭；
- 不得一闪而过；
- 负数使用明确符号；
- 隐藏属性不显示具体数值时，显示札记反馈。

## 示例

```text
顾明川把最后一角油布压在箱底，朝你点了点头……
实务 +4｜校园秩序 +3｜体力 -2
顾明川信任 +3
【后续影响】缺失箱号将在次日校务处继续核对。
```

## 验收

使用三个事件、九个分支逐一测试：

- 所有反馈文字不同；
- 所有数值正确；
- 所有旗标正确；
- 时间只推进一次；
- 晚间结束后强制回宿舍。
